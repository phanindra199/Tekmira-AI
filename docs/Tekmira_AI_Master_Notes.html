1. Executive Summary & Problem Modeling

1.1 The Campus Placement Crisis: The Resume Inflation Trap

In modern technical recruitment and college placement drives, candidates are evaluated almost exclusively on textual claims presented in resume PDFs. Due to the proliferation of keyword-stuffing templates and generative AI resume builders, technical resumes are experiencing massive inflation:

  • Candidates claim proficiency in advanced systems (e.g., Docker, Kubernetes, Redis, Microservices, React, GraphQL) after only watching a tutorial or copying a boilerplate.
  • Traditional Applicant Tracking Systems (ATS) rely on superficial string-matching algorithms, rewarding candidates who stuff buzzwords while penalizing genuine software developers who describe real implementation trade-offs without marketing jargon.
  • Technical interviewers waste dozens of engineering hours conducting interviews only to discover candidates cannot explain or write fundamental code for the frameworks claimed on their resumes.
  • Students receive zero objective, empirical feedback regarding whether their actual written code matches hiring standards for specific campus roles.
The Fundamental Defect of Existing AI Resume Screeners
Evaluating a resume PDF using an LLM (such as raw ChatGPT or Claude) does not solve resume inflation; it amplifies it. An LLM processing a resume alone can only evaluate the elegance of the claim, not the empirical truth of the implementation. To establish objective truth, software evaluation requires deterministic multi-source cross-verification.

2. The Core Solution: The 3-Way Triangulation Engine

Tekmira AI replaces ungrounded claims with 3-Way Empirical Triangulation. The platform reconciles three completely independent vectors of data before computing a candidate's Placement Readiness Index:

1. Claimed Competency

Extracted from Candidate Resume PDFs

What the candidate claims they know. Mined via natural language stream parsing, identifying self-reported technical skills, libraries, tools, and reported project scopes.

2. Empirical Proof

Mined from Public GitHub Repositories

What the candidate has actually built. Mined via Octokit REST API, extracting authentic commit histories, author verification, language AST distributions, package manifests, and test coverage.

3. Industry Benchmark

Parsed from Real Campus Job Descriptions

What the job market requires. Normalized skills, required competencies, and minimum experience thresholds ingested from real campus hiring specifications.

3.2 The Critical Architectural Pattern: app.js vs server.js

A frequent architectural blunder in junior Express applications is calling app.listen() inside the same file where middleware, routes, and error handlers are configured. Tekmira AI rigorously enforces the Decoupled Server Pattern:

Figure 1.2: App vs Server Separation of Concerns
Viva Voce Defense: Why Separate app.js from server.js?
If app.listen() is invoked in the same file where routes are declared, importing the app in automated test suites (such as Jest or Supertest) will attempt to bind to physical port 5000 during test execution. In continuous integration (CI) pipelines or parallel test runners, this causes immediate EADDRINUSE: address already in use crashes. By keeping app.js purely as an exported middleware pipeline, Supertest can inject simulated HTTP requests directly into the Express kernel in memory without requiring network binding.

5. Day 3: JavaScript Core Foundations, Safe API Client & Defensive Error Handling

5.1 JavaScript Engine Fundamentals

On Day 3, we documented the critical V8 engine mechanics in [docs/VIVA_PREP.md](file:///docs/VIVA_PREP.md) and applied them directly into production code:

1. Hoisting & The Temporal Dead Zone (TDZ)

In JavaScript, variable declarations are processed during the Creation Phase of the Execution Context before any code runs. Variables declared with var are allocated in memory and initialized to undefined. Variables declared with let and const are also allocated in memory, but they remain uninitialized. The window between entering the scope and reaching the lexical declaration is the Temporal Dead Zone (TDZ). Accessing a variable in the TDZ throws an immediate ReferenceError.

2. Closures in Token Management & Debounce

A closure is the combination of a function bundled together with references to its surrounding lexical environment. In Tekmira AI, closures are leveraged in apiClient.js to maintain private authentication state, and in input debouncing to prevent excessive API invocations when candidates type repository URLs.

3. The V8 Event Loop: Microtasks vs Macrotasks

The JavaScript single-threaded concurrency model manages asynchronous events through two distinct queues:

  • Microtask Queue (Higher Priority): Holds callbacks from Promise.then/catch/finally, await continuations, and queueMicrotask().
  • Macrotask Queue (Lower Priority): Holds callbacks from setTimeout, setInterval, setImmediate, and I/O polling.

5.2 Sanitized Error Normalization (`client/src/utils/apiError.js`)

A major security risk in web development is leaking internal backend diagnostics (e.g., PostgreSQL credentials, stack traces, MongoDB connection strings) to client browsers. Tekmira AI implements normalizeApiError(), which maps all failures into 8 structured types and applies strict production credential masking: 

// client/src/utils/apiError.js - Sanitized Error Normalization
export function normalizeApiError(error) {
  if (axios.isCancel(error)) {
    return { type: 'REQUEST_CANCELLED', message: 'Request was cancelled.', status: 0 };
  }
  if (!error.response) {
    return { type: 'NETWORK_ERROR', message: 'Unable to reach Tekmira server. Verify connection.', status: 0 };
  }
  const status = error.response.status;
  if (status === 400) return { type: 'VALIDATION_ERROR', message: error.response.data.message, errors: error.response.data.errors, status };
  if (status === 401) return { type: 'UNAUTHORIZED', message: 'Session expired. Please log in.', status };
  if (status === 403) return { type: 'FORBIDDEN', message: 'Access denied.', status };
  if (status === 404) return { type: 'NOT_FOUND', message: 'Requested resource not found.', status };
  
  // CRITICAL SECURITY RULE: Mask 500 errors to prevent credential leakage
  return { 
    type: 'SERVER_ERROR', 
    message: 'An internal server error occurred. Our engineering team has been notified.', 
    status: 500 
  };
}

5.3 Lifecycle Unmount Safety with `AbortController`

In React 18 Concurrent Mode, components may unmount while asynchronous HTTP network requests are in-flight. If a component updates state on an unmounted DOM node, memory leaks and stale UI flashes occur. Tekmira AI binds browser-native AbortController instances inside useEffect cleanups: 

useEffect(() => {
  const controller = new AbortController();
  
  async function fetchBackendHealth() {
    try {
      const res = await apiClient.get('/health', { signal: controller.signal });
      setStatus(res.data.status);
    } catch (err) {
      if (!axios.isCancel(err)) setStatus('error');
    }
  }
  fetchBackendHealth();

  // Cleanup: Terminate in-flight network request on unmount
  return () => controller.abort();
}, []);

6.2 Relational Query Service: SQL JOIN Equivalents

In [`server/src/services/jobApplicationService.js`](file:///server/src/services/jobApplicationService.js), we implemented explicit SQL JOIN equivalents using Prisma ORM:

  • INNER JOIN Equivalent: Queries jobApplication.findMany() with include: { user: true, job: true }. Only returns applications where both the user identity and the benchmark job record exist.
  • LEFT JOIN ... WHERE NULL Equivalent: Identifies registered candidates who have never submitted an application by querying user.findMany() with where: { applications: { none: {} } }.
  • Aggregation Queries: Calculates average candidate match score and application status counts grouped by target company.
SQL Injection Prevention Mechanics
Prisma completely neutralizes SQL Injection vulnerabilities because it converts all application queries into parameterized SQL statements (using placeholders $1, $2, $3). User-supplied inputs are never concatenated directly into the SQL string; the database engine treats them strictly as literal parameter values.

8. Day 6: Authentication & Middleware Security (Bcrypt + JWT)

8.1 Password Hashing Mechanics with Bcrypt

Passwords are never stored in plaintext. In [`server/src/services/authService.js`](file:///server/src/services/authService.js), passwords undergo cryptographic adaptive hashing via bcryptjs with 10 salt rounds:

Figure 1.7: Cryptographic Password Hashing Lifecycle

8.2 Stateless JWT Architecture & Role-Based Access Control (RBAC)

Tekmira AI relies on stateless JSON Web Tokens (JWT) signed using HS256 (HMAC with SHA-256):

  • Payload: Encodes user identification (id), email (email), and authorization tier (role: 'CANDIDATE' | 'ADMIN').
  • `authenticate` Middleware: Extracts the Authorization: Bearer <token> header. If missing, malformed, or expired, halts with HTTP 401 Unauthorized. Attaches safe req.user.
  • `authorizeRoles(...roles)` Middleware: Inspects req.user.role. If the candidate lacks clearance, halts with HTTP 403 Forbidden.
  • Sanitization: AuthService.sanitizeUser() explicitly deletes passwordHash from returned objects.

12. Master Viva Voce & Technical Defense Cheat Sheet

Essential academic questions, architectural rationales, and defense points for examiners and project assessors:

Examiner Question Academic Focus Authoritative Technical Defense
Why not just evaluate resumes with ChatGPT or Gemini directly? AI Architecture & Hallucination Prevention LLMs evaluating only a resume evaluate claims, not evidence. This rewards resume inflation and causes severe hallucination. Tekmira AI grounds evaluation by cross-verifying resume claims against empirical GitHub commit code and objective job benchmarks.
Why separate app.js from server.js? Separation of Concerns & Automated Testing app.js configures middleware and routes without binding to a physical network port, allowing automated testing libraries (Supertest) to test endpoints in-memory without EADDRINUSE port collisions. server.js manages process listening and graceful OS shutdown signals.
Why use UUIDs instead of auto-incrementing integers? Database Security & Privacy Sequential IDs (1, 2, 3...) are vulnerable to enumeration attacks where malicious actors guess other candidate IDs. UUIDv4 provides 128-bit globally unique, unguessable identifiers.
Why use both PostgreSQL and MongoDB (Polyglot Persistence)? Data Modeling Fundamentals Relational data with strict foreign keys and ACID constraints belongs in PostgreSQL (Users, Job Postings, Applications). Polymorphic, deeply nested trees (resume ASTs, commit trees, and AI reports) belong in MongoDB.
What is the Microtask Queue vs Macrotask Queue in the Event Loop? JavaScript Runtime Internals The Microtask Queue (Promise callbacks, await continuations) has higher priority. The Event Loop exhausts all pending microtasks immediately after the Call Stack empties and before executing the next Macrotask (setTimeout, I/O).
How does Prisma ORM prevent SQL Injection? Web Application Security Prisma automatically converts all queries into parameterized queries ($1, $2), treating user inputs strictly as literal data rather than executable SQL syntax.
Why use `bcrypt` salts and work factors? Cryptographic Security The salt ensures identical passwords produce distinct hashes, neutralizing precomputed Rainbow Table attacks. The configurable work factor (10 rounds) makes brute-force cracking computationally prohibitive.
Why should RESTful endpoints use nouns instead of verbs? REST Constraints In REST, URIs represent resources (nouns like /jobs), while HTTP verbs (GET, POST, PUT, DELETE) communicate the operation. Using verbs in URIs violates the Uniform Interface constraint.
Why validate request payloads at runtime with Zod? Defensive API Design TypeScript or JavaScript type assertions only exist at compile time; runtime attacks, malformed JSON, and unexpected nulls occur in production. Zod validates boundaries before inputs reach database queries.
