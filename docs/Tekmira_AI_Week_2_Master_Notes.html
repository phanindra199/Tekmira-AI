1. Week 2 Strategic Vision & Architectural Blueprint

In Week 1, Tekmira AI established its relational foundation: PostgreSQL schema migration, Prisma ORM queries, MongoDB polyglot health connectivity, and JWT security boundaries. In Week 2 (Days 8–14), the platform transitioned from a structural data harness into a production-grade Empirical Verification Engine.

Traditional recruitment and campus placement systems rely on self-reported resume claims and keyword matching. This creates widespread credential inflation: candidates copy buzzwords into their resumes that have never been substantiated in real-world software development. Tekmira AI fundamentally dismantles this asymmetry by enforcing a strict 3-Way Empirical Triangulation:

1. Candidate Resume Claims

Parsed directly from authenticated PDF text streams using deterministic character boundary checks and extracted into structured competencies using Google Gemini 2.5 Flash with strict JSON schema enforcement.

2. Public GitHub Empirical Proof

Mined from authentic Git commits, verified author identities, AST manifest dependencies (e.g. package.json, pom.xml), and test harness presence (Jest, Supertest, PyTest) using recursive Git trees.

3. Target Job Benchmark Criteria

Normalized against campus placement profiles stored in PostgreSQL, establishing mandatory technical prerequisites and skill importance weights.

2. Day 8 — Google Gemini 2.5 Integration & Resilient AI Gateway

2.1 The Official Google Gen AI SDK Architecture

Tekmira AI standardizes exclusively on the modern, high-performance @google/genai SDK (not the deprecated @google/generative-ai). The integration is encapsulated within server/src/services/aiService.js, utilizing Google's flagship reasoning model: gemini-2.5-flash.

As a Senior Staff Software Engineer, designing an external AI integration requires assuming external service degradation, network partitions, rate limiting, and quota exhaustion from Day 1. The service follows three core tenets:

  • Client Factory Pattern: A singleton getGenAIClient() instance evaluates GEMINI_API_KEY at execution time, preventing crash-on-import if environment variables are delayed.
  • Fail-Safe Fallback Mocking: When running in disconnected test environments or before the developer configures their API key, the gateway transparently routes requests to deterministic internal mock extractors rather than blowing up runtime pipelines.
  • Strict System Instruction Separation: System identity guidelines are passed through dedicated systemInstruction options, isolating trusted prompt instructions from untrusted user content (preventing indirect prompt injections).

2.2 Implementation: Resilient Gateway Logic

// server/src/services/aiService.js
import { GoogleGenAI } from '@google/genai';
import { env } from '../config/environment.js';
import { logger } from '../utils/logger.js';

let genAIClient = null;

export const getGenAIClient = () => {
  if (genAIClient) return genAIClient;
  const apiKey = env.GEMINI_API_KEY;
  if (!apiKey || apiKey.trim() === '' || apiKey.includes('your_gemini_api_key')) {
    logger.warn('Gemini API key not configured. Using deterministic fallback mock.');
    return null;
  }
  genAIClient = new GoogleGenAI({ apiKey });
  return genAIClient;
};
⚠️ Engineering Pitfall: Unchecked LLM Dependencies

Never allow an unhandled GoogleGenAI rejection to crash your Express event loop. Always wrap generative calls in localized try/catch blocks that normalize API rate limits (HTTP 429) and invalid token errors (HTTP 401) into standardized AppError instances with user-friendly remediation messages.

3. Day 9 — Prompt Engineering & Zero-Hallucination Schemas

3.1 The Zero-Hallucination Guarantee

The fatal flaw of naive LLM wrappers in HR tech is stochastic hallucination: the model invents skills the candidate never possessed, or manufactures false project details. Tekmira AI establishes mathematical certainty by enforcing Structured Outputs via Gemini's native responseSchema and responseMimeType: 'application/json'.

When schema constraints are passed directly to the model's decoding sampler, the transformer is constrained at the token probability level: it is physically incapable of emitting tokens that violate the specified JSON schema.

3.2 Dual Schema Architecture: OpenAPI Engine & Zod Security Boundary

Tekmira AI implements a robust dual-schema design pattern in server/src/validations/structuredOutputSchemas.js:

  1. OpenAPI-compliant JSON Schemas: Fed to the Gemini 2.5 decoding engine (geminiResumeSkillsJsonSchema, geminiInterviewQuestionsJsonSchema).
  2. Zod Schemas: Applied to parsed JSON objects in the Node.js runtime to sanitize types, strip extraneous fields, and enforce structural invariants (ExtractedResumeClaimsSchema, InterviewQuestionSchema).
// OpenAPI JSON Schema for Gemini Engine Sampler
export const geminiResumeSkillsJsonSchema = {

        type: 'object',

4. Day 10 — Secure PDF Upload, Magic Bytes & Text Parsing

4.1 Binary Defense & The Magic Byte Principle

File upload endpoints are among the highest-risk attack surfaces in web applications (susceptible to remote code execution, zip bombs, and MIME-type spoofing). Attackers frequently rename executable binaries (e.g. malware.exe) to resume.pdf to bypass naive file extension checks.

Tekmira AI enforces a multi-tiered binary validation gateway in server/src/middleware/uploadMiddleware.js:

  • Multer In-Memory Storage: File buffers are held strictly in RAM (max 5MB limit). Files are never written to the host filesystem prior to validation, preventing malicious disk writes.
  • Magic Byte Verification: The first 5 bytes of the binary buffer are inspected for the mandatory PDF signature: %PDF- (hexadecimal: 25 50 44 46 2D). Any file lacking this exact prefix is aborted immediately with HTTP 415 Unsupported Media Type.
  • SHA-256 Deduplication: Every uploaded document is hashed (crypto.createHash('sha256')). The hash is indexed in MongoDB to immediately detect duplicate uploads without redundant LLM reprocessing.
  • Scanned Image Detection: If the text extraction yields 0 characters, the document is flagged as isScanned: true. Tekmira AI explicitly rejects OCR hallucination, demanding clean selectable text streams.

5. Day 11 — GitHub REST API Evidence Mining & Code Provenance

5.1 Deep Repository Mining Architecture

In server/src/services/githubService.js, Tekmira AI interfaces with the GitHub REST API v3 to transform a public repository into an empirical proof graph. The engine executes three discrete mining phases:

Phase A: Recursive Git Tree Traversal

Rather than cloning gigabytes of source code onto the server disk, the engine retrieves the repository's tree structure via GET /repos/{owner}/{repo}/git/trees/{branch}?recursive=1. This allows the backend to catalog every file path, file extension, and directory depth in a single lightweight HTTP request.

Phase B: Language Distribution & Manifest Dependency Extraction

The service queries GET /repos/{owner}/{repo}/languages to calculate exact byte ratios and percentages. Simultaneously, the engine scans the tree for package manifests and fetches their contents via raw GitHub URLs:

  • package.json: Scanned for dependencies and devDependencies (React, Prisma, Express, Tailwind, Jest).
  • pom.xml / build.gradle: Scanned for Java ecosystem libraries (Spring Boot, Hibernate, JUnit).
  • requirements.txt / pyproject.toml: Scanned for Python frameworks (FastAPI, Django, PyTorch).
  • Test Suite Discovery: Tree inspected for /test/, __tests__, *.test.js, or *.spec.ts.

Phase C: Author Verification & Commit Provenance

To verify that the candidate actually authored the code (rather than forking an open-source template), the service retrieves recent commit history (GET /repos/{owner}/{repo}/commits) and compares the commit author email against the candidate's registered profile.

6. Day 12 — 3-Way Triangulation & Placement Readiness Index (PRI)

6.1 The Mathematical 3-Way Triangulation Matrix

The heart of Tekmira AI is the Triangulation Engine in server/src/services/matchingEngine.js. Every technical competency is projected across three distinct boolean dimensions:

  • Claimed ($C \in \{0, 1\}$): Did the candidate state this skill on their resume?
  • Demonstrated ($D \in \{0, 1\}$): Is there authentic evidence in their GitHub commits, dependencies, or test suites?
  • Required ($R \in \{0, 1\}$): Is this skill required by the target campus job description?
Triangulation Classification $C$ $D$ $R$ Status Interpretation & Placement Impact
VERIFIED 1 1 1 Full Match High confidence. Claimed, validated by code evidence, and satisfies employer need.
INFLATED_CLAIM 1 0 1/0 Risk Warning Buzzword copied onto resume without a single line of supporting repository evidence.
UNCLAIMED_STRENGTH 0 1 1/0 Bonus Asset Proven in repository code (e.g. automated testing) but candidate neglected to list it.
MISSING_CRITICAL 0 0 1 Immediate Blocker Required by target benchmark role, but absent from both resume and GitHub.

6.2 The Placement Readiness Index (PRI) Mathematical Formula

Tekmira AI avoids arbitrary scoring. The Placement Readiness Index (PRI) is computed using an objective weighted multi-factor formulation:

PRI = \min\left(100, \; \max\left(0, \; \Big( \frac{V}{N_{req}} \times 55 \Big) + \Big( \frac{B}{N_{req}} \times 15 \Big) + \big( T_{score} \times 0.15 \big) + \big( D_{score} \times 0.15 \big) - \big( I \times 5 \big) \Big)\right)\right)

Where:

  • $V$: Count of strictly VERIFIED core requirements.
  • $N_{req}$: Total number of requirements specified by the target benchmark role.
  • $B$: Count of UNCLAIMED_STRENGTHS (bonus competencies demonstrated in code).
  • $T_{score}$: Testing Rigor Score ($0$ to $100$, evaluated by test harness presence and assertion counts).
  • $D_{score}$: Architecture & Documentation Depth ($0$ to $100$, evaluated by README, multi-layer separation).
  • $I$: Count of INFLATED_CLAIMS (penalized at 5 points per unsubstantiated claim).

7. Day 13 — Executive Analysis Dashboard & Reactive UI

7.1 Component Architecture & Async Lifecycle Management

Implemented in client/src/pages/DashboardPage.jsx, the Placement Readiness Dashboard translates complex triangulation matrices into an intuitive, actionable executive interface.

In modern React applications, handling asynchronous network data without race conditions or memory leaks requires strict adherence to cleanup contracts:

  • AbortController Signal Binding: Every fetch request passes an abort signal. If the candidate switches tabs or navigates away, inflight HTTP requests are aborted cleanly.
  • Mounted State Guards: Component state setters are guarded with if (isMounted) to prevent React unmounted component warnings.
  • Radial SVG Meter: An interactive, mathematical SVG gauge renders the PRI score dynamically using strokeDasharray and strokeDashoffset calculated from $2\pi r$.
  • 3-Way Filterable Skills View: Candidates can toggle between All Skills, Verified Proofs, Inflated Claims, and Missing Prerequisites.
// client/src/pages/DashboardPage.jsx (Async Lifecycle Pattern)
useEffect(() => {
  const controller = new AbortController();
  let isMounted = true;

  async function loadDashboard() {
    try {
      setIsLoading(true);
      const res = await repositoryService.triangulateSkills({ signal: controller.signal });
      if (isMounted) {
        setReport(res.data);
      }
    } catch (err) {
      if (!controller.signal.aborted && isMounted) {
        setErrorMessage(err.message || 'Failed to load report');
      }
    } finally {
      if (isMounted) setIsLoading(false);
    }
  }

  loadDashboard();
  return () => {
    isMounted = false;
    controller.abort();
  };
}, []);

8. Day 14 — AI Technical Viva Voce & Rubric Grading

8.1 Grounded Codebase Defense Philosophy

Standard technical interviews suffer from two extremes: shallow algorithmic trivia (LeetCode) or generic conversational trivia. In contrast, academic degree defenses and senior staff interviews demand Codebase Grounding: defending the exact design trade-offs, architecture decisions, and error-handling mechanisms in code the candidate personally wrote.

In server/src/services/interviewService.js, Tekmira AI generates viva questions anchored directly in the candidate's mined repository files:

  • File Citation: Every question explicitly cites a real file (e.g. server/src/app.js, prisma/schema.prisma).
  • Architectural Scaffolding: Questions target architectural concepts (e.g. Polyglot Persistence Synchronization, Token Expiry vs Refresh Invalidation).
  • Zero Trivia Guarantee: The AI is forbidden from asking generic dictionary definitions; it must ask how the candidate handled concurrency, exceptions, or security boundaries.

8.2 The 3-Part Academic Evaluation Rubric

When a candidate submits their technical answer, Gemini 2.5 evaluates the response across three distinct rubric dimensions specified in server/src/prompts/promptTemplates.js:

Rubric Dimension Weight Evaluation Criteria
Technical Accuracy 40% Correctness of underlying computer science concepts, protocols, database mechanics, and runtime behaviors.
Evidence Awareness 35% Direct familiarity with their own implementation files, functions, error handling, and trade-offs.
Conceptual Clarity 25% Structure, precision, terminology, and ability to articulate architectural trade-offs without buzzwords.
🛡️ Ethical AI Boundary: Formative Feedback Disclaimer

In accordance with academic fairness standards, all automated interview evaluations generated by Tekmira AI explicitly carry the ethical advisory notice: "This evaluation is formative feedback powered by AI assistance and does not constitute an official academic grade or final employment guarantee."

12. Senior Technical Viva Voce Defense Compendium

The following questions and in-depth answers represent the exact technical rigor expected by senior software architects, university assessment panels, and principal engineers during an oral defense of Tekmira AI.

Q1: Why did you choose Google Gemini 2.5 Flash over OpenAI GPT-4o or Claude 3.5 Sonnet for this platform?
Answer: We selected gemini-2.5-flash for three architectural reasons: 1) Low Latency & High Throughput: Flash delivers sub-second token generation latencies essential for synchronous interactive viva voce evaluations; 2) Native Structured Output Enforcement: Gemini’s API supports native JSON Schema sampling at the decoding layer (responseSchema), eliminating markdown parsing regexes; 3) Cost & Context Capacity: Gemini 2.5 Flash offers a 1-million-token context window with significantly lower inference costs, enabling ingestion of large AST manifests and multiple candidate files simultaneously without truncation.
Q2: How does Tekmira AI prevent a candidate from tricking the system by uploading a renamed executable binary as a PDF?
Answer: We do not rely on MIME headers or file extensions sent by the client, which can be trivially forged in HTTP requests. Our custom validateUploadedPdf middleware reads the raw buffer in RAM and validates the mandatory 5-byte file header magic number: %PDF- (ASCII bytes 0x25, 0x50, 0x44, 0x46, 0x2D). If these exact bytes are not present at offset 0, the request is immediately rejected with HTTP 415.
Q3: How does your system differentiate between an authored repository and a cloned/forked open-source repository?
Answer: We evaluate three empirical signals via the GitHub API: 1) The repository metadata fork boolean flag; 2) The commit provenance log (comparing commit author emails against the candidate’s registered email address); 3) The proportion of commit history authored by the candidate versus upstream contributors. If a candidate claims a repository where 0% of the commits match their email, the code evidence is rejected as unverified.
Q4: Explain the mathematical intuition behind the Placement Readiness Index (PRI) formula. Why penalize inflated claims?
Answer: The PRI formula is designed around evidence confidence. Verified core requirements contribute the foundational 55% of the score. Testing rigor and documentation contribute 30% combined because production readiness requires maintainability, not just syntax. Crucially, inflated claims incur a negative penalty (-5 points each) to actively discourage "resume stuffing" — candidates who list 50 buzzwords without proof are penalized relative to candidates who list 5 skills and prove all 5 in code.
Q5: How does your viva voce engine prevent LLMs from asking generic trivia questions?
Answer: We utilize codebase-grounded prompt templates. In createGroundedQuestionPrompt, we supply the model with the candidate's exact repository snapshot, including file paths and manifest dependencies. The prompt strictly instructs the model: "You must anchor the question in the specific implementation file. Ask how the candidate implemented error handling, state synchronization, or database constraints in that file. Never ask trivia definitions."
Q6: Why did you adopt a polyglot persistence model (Postgres + Mongo) instead of keeping everything in Postgres?
Answer: Relational databases excel at ACID transactions, referential integrity, and join queries across tabular entities (Users, Colleges, Job Benchmarks). However, raw resume text, AST file trees, triangulation matrices, and LLM evaluations are deeply nested, polymorphic JSON documents that evolve frequently. Storing them in MongoDB preserves native JSON querying, avoids expensive relational normalization across 15 join tables, and enables document-level atomic updates.
